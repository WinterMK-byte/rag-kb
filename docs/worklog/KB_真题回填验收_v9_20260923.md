## 二、四层根因（逐层查实）

1. **v8 是「只重算向量」的派生库** —— `config.json` 写 `parent_store=vector_store_v7` +「无需重新解析源文件」
   → **从未重扫磁盘**。新目录只要不在 v7 里，就永远进不来。
2. **`.jpg` 被设计为不入正文** —— `META_ONLY_EXT` 不解析图片；能否检索**完全取决于 `text_cache` 有没有它的 OCR 正文**。
3. **`text_cache` 已不存在** —— v8 指向的 Marvis 会话 temp 被清、知识库下无 `text_cache\`、Marvis 侧 `math_kp\pages` 也已清 → **零可复用 OCR 文本**。
4. **增量会自动清失效条目** —— 旧路径 `Resource\真题\` 的 10 文件 / 44 条会被移除 → 不同步补 OCR 就会**真丢内容**。

## 三、修复（4 步）

1. **本地免费 OCR 51 张真题图**（`rapidocr_onnxruntime`，单 worker 串行、内存增量仅 ~190 MB、共 5.9 分钟）
   → 写 `本地知识库\text_cache_zhenti\<sha1(绝对路径)>.txt`，正文前注入标题头：
   ```
   【资料】院校B真题/2023年院校B-01.jpg
   【文件名】2023年院校B-01.jpg
   <OCR 正文>
   ```
2. 生成强制重嵌清单 `v9_force_zhenti.json`（52 条 = 51 jpg + `真题.pdf`）。
3. 复制 v8 旧库五件套 → `vector_store_v9`（**不从零重建**）。
4. `build_kb_v3.py --out vector_store_v9 --text-cache text_cache_zhenti --force-list …` 覆盖式重嵌（2.0 分钟，`failed=0`）。
