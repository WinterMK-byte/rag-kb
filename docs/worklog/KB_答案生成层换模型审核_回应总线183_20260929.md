# RAG 答案生成层换模型审核结论（回应总线 #183）

> 交接件：`30_协作\30_交接_RAG答案生成层换deepseek-v4-flash_20260929.md`
> 提议：`kb_search_v3.py` L60 `DEEP_MODEL = 'glm-5.2'` → `'deepseek-v4-flash'`
> 理由（交接件）：glm-5.2 实测 **10.8s 且易 429**；deepseek-v4-flash **2.5 / 5.3s**；零成本同池
> 审核方：RAG 线｜日期：2026-09-29｜**全程只读，未改任何 .py**

## 零、结论速览

**实测后不建议更换。交接件的两条核心收益，在生产配置下一条不成立、一条方向相反。**

| 交接件的论据 | 实测结果 | 判定 |
|---|---|---|
| glm-5.2 单次 10.8s | 无重试 3.6 / 6.8 / 4.9s，均 **5.1s** | ❌ 数字不复现 |
| flash 单次 2.5 / 5.3s | 无重试 3.3 / 429 / 5.2s，均 **4.2s** | ⚠️ 仅快 0.9s，且 3 次里挂 1 次 |
| 「提速 2-4 倍」 | **retries=2（生产）**：glm **均 6.3s / 中位 4.7s**；flash **均 8.7s / 中位 11.5s** | ❌ **flash 反而更慢** |
| 「消除 429」 | retries=0：两模型各 **8/10**；retries=2：两模型各 **10/10** | ❌ 429 特性相当，且生产下都被重试吸收 |
| 验收「kb_eval 不劣化」 | `kb_eval.py` 里 `DEEP_MODEL` 出现 **0 次** | ⚠️ **无效验收**（数学上不可能变） |

**质量侧：两模型均无幻觉，引用标注都稳；flash 有 LaTeX 渲染与「资料未提及」的严谨表述两个可取之处，但 glm-5.2 更凝练。** 综合「无收益 + 反向变慢 + 需额外改动」，**不动**。

## 一、交接件的四处遗漏与一处错判（先修事实）

### 遗漏 1：`kb_answer.py` L418 —— 自校验路径**也**用 `DEEP_MODEL`（交接件只列了 L380/382）

```
L380/382  云端答案生成   model=k3.DEEP_MODEL   retries=2, num_predict=3000
L391      失败回退本地   qwen2.5:7b
L418      自校验 VERIFY  model=k3.DEEP_MODEL   retries=1, num_predict=400   ← 交接件漏
```

**影响**：每次答案生成实际是 **`DEEP_MODEL` 调两次**（生成 + 自校验）。所以「单次延迟」的真实放大倍数是 2×，交接件按 1× 估算的快慢差异**整体被低估**。

### 遗漏 2：`kb_ask.py --mode` 默认是 `fast`，不是 deep

`kb_ask.py` L396 `--mode default='fast'`；L175 只有 `--mode deep` 才注入 `model=k3.DEEP_MODEL`。**默认路径根本不走 `DEEP_MODEL`**（走本地 `qwen2.5:7b`）。交接件写「每次 kb_ask 的答案生成都在跑那个慢的」——对**默认档不成立**。

### 错判 3：验收第 3 条「kb_eval 不劣化」是**无效验收**

机器核实（`kb_eval.py` 全文关键字计数）：

```
DEEP_MODEL : 0 次        answer(  : 0 次
FAST_MODEL : 0 次        llm_call : 0 次
k3.        : 1 次   ← 仅 k3.CACHE_DIR（取重排缓存路径）
```

`kb_eval.py` 只跑**检索层**（rewrite → BM25+dense → rerank），**完全不引用答案生成**。换 `DEEP_MODEL` 在数学上不可能影响 Hit@1/Hit@3/MRR。这条验收**换成任何模型都会「通过」**，不具备判别力，应从验收清单移除。

### 遗漏 4：交接件给的 0.794 MRR 基线偏低

交接件引的基线是「70.6-88.2-94.1-MRR0.794」。RAG 线现行冷口径是 **Hit@1 70.6% / Hit@3 94.1% / Hit@5 100% / MRR 0.819**（2026-09-27 #148 定案）。**Hit@3 与 MRR 都对不上**，交接件抄的是更早的一份数（见 2026-09-26 旧基线 `eval_final_rerank.json` 67.6%/MRR 0.811 一系）。不影响本审核结论，但后续引数请以 #148 为准。

## 二、延迟实测（这是我推翻交接件的主要依据）

### 2.1 无重试单发（`retries=0`，`num_predict=800`，同 prompt）

| 模型 | 第 1 次 | 第 2 次 | 第 3 次 | 均值 |
|---|---|---|---|---|
| `glm-5.2` | 3.6s | 6.8s | 4.9s | **5.1s** |
| `deepseek-v4-flash` | 3.3s | **429** | 5.2s | 4.2s |

→ **交接件「glm-5.2 = 10.8s」不复现**（本次最快 3.6s）。两者都在 3~7s 区间，**差距不到 1s**。

### 2.2 连跑 10 次（`retries=0`，裸测 429 率）

| 模型 | 成功 | 失败原因 | 均延迟 |
|---|---|---|---|
| `glm-5.2` | **8/10** | 2 次 **27.3s 超时** | 3.9s |
| `deepseek-v4-flash` | **8/10** | 2 次 **8.3s 429** | 3.6s |

→ **两模型失败率完全相同（各 2/10）**，只是失败形态不同：glm 挂超时、flash 挂 429。**「flash 消除 429」不成立**。

### 2.3 🔴 连跑 10 次（`retries=2`，**生产实际配置**）—— 决定性结果

| 模型 | 成功 | 跨过 429 失败 | 均值 | **中位数** | max |
|---|---|---|---|---|---|
| `glm-5.2` | **10/10** | **0** | **6.3s** | **4.7s** | 14.8s |
| `deepseek-v4-flash` | **10/10** | **0** | **8.7s** | **11.5s** | 13.0s |

**结论反过来**：免费池限流下，flash 触发 429 后走重试（每次 **+8s**），**中位延迟 11.5s 是 glm-5.2 的 2.4 倍**。

- 交接件设想的「2.5s 档」只在**未触发限流**时才有；免费池共享，一旦触发，重试成本远高于省下的时间。
- 生产两个模型都**不会**把 429 抛给用户（重试吸收），所以「消除 429」这个收益**在用户体验上并不存在**。
- 而 `kb_answer` 是**生成 + 自校验两次调用** → 上述差距 **×2**（glm ≈ 12.6s / flash ≈ 17.4s 均）。

## 三、质量 A/B（3 组真实查询，同检索上下文，只换生成模型）

| 维度 | `glm-5.2` | `deepseek-v4-flash` |
|---|---|---|
| 引用标注 | 稳（`[1]`/`[2]`/`[4]`） | 稳，**更细**（引到 `[1] 定理7` 级别） |
| 公式渲染 | LaTeX | LaTeX，**更规范**（`\frac{0}{0}`、`\infty` 完整） |
| 治学严谨 | 直接作答 | **明说「资料未提及失效情形」**（不脑补） |
| 篇幅 | **凝练** | 明显更长 → **更易触发截断标记** |
| 幻觉 | 无 | **无** |

**无幻觉验证（三个陷阱测试，双方一致通过）**：

| 陷阱 | `glm-5.2` | `deepseek-v4-flash` |
|---|---|---|
| A 问不存在的实体 | 正确拒答 | 正确拒答 |
| B 问资料里没有的考点 | 正确拒答 | 正确拒答 |
| C 跨资料常识题 | 正确作答 | 正确作答（答 `1/e` 并标 `[1]`） |

**勘误自纠**：我首轮 A/B 见 flash 给 `2023 院校D lim(n/(n+2))^n` 补答「1/e」，一度判为幻觉。复查 ctx 原文是 `(2023 院校D)求极限 lim (n/(n+2))^n 。 【 / e】`——**答案本就是 1/e，只是 OCR 把 `1` 吞了**。flash 是从残缺符号**推断**出 `1/e`，属能力而非缺陷。

**质量小结**：**两者都没有跑赢对方一个身位**。flash 占「表述严谨 + 公式清晰」，glm-5.2 占「凝练 + 长答案不截断」。质量不构成更换理由，也不构成拒绝理由——**是收益侧全空，才决定不动**。

## 四、若要换，必须同时处理的三件事（供参考，本次不执行）

1. **自校验路径**（`kb_answer.py` L418）也要一起评估——否则「换模型」实际只改了 1/2 次调用，评估口径不成立。
2. **截断风险**：flash 答案更长，`kb_search_v3` 的 `CLOUD_MAX_TOKENS=1200` 与 `kb_answer` 的 `num_predict=3000` 需重新校验；`truncated` 判据（末尾不在 `。！？；）】》.!?`）会因 LaTeX 结尾而误判。
3. **验收清单重写**：删掉无效的「kb_eval 不劣化」，改为「**答案生成 P50/P95 延迟实测对比** + **连跑 10 次的答案完整率**（非 429 率）」。

## 五、建议（三选一，我推荐 A）

| 方案 | 动作 | 代价 | 结论 |

| **A（推荐）** | **不动**，保留 `glm-5.2`；把本审核结论回写交接件 | 0 | ✅ 实测收益为零、flash 反向变慢；无理由为一个「更慢但风格不同」的模型改生产路径 |
