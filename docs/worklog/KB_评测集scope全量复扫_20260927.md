### ⚠️ 本轮踩到的两个假阳性（**判据本身要修正**，已被本轮剔除）

**假阳性 1 —— `auto` 是路由别名，不是过滤域。**
`a01` / `a02` 标注 `scope=auto`。而 `scope_list('auto') = ['auto']`，`SCOPE_RULES` 里没有 `'auto'` 键
→ 直接喂给 `in_scope()` **恒返回 False** → 第一版扫描把它们误报成「233 / 64 条全部域外」。
**修法**：先调 `kb_ask.auto_scope(q)` 路由成真实域（`a01→kmath` / `a02→ken`），再判。
路由后：`a01` 233 个文件全在域内 ✅，`a02` 64 个全在域内 ✅。
（`kb_eval.py::_resolve_scope()` 干的就是这件事，见其源码。）

**假阳性 2 —— `mathdoc ⊂ gmath`，`scope_of()` 字面比较会误报。**
`c03`（标 `gmath`）/ `c08`（标 `gmath`）的期望文件实为 `mathdoc`（`SCOPE_RULES` 的 `gmath` = `ECUST课程资料\数学学院`，而 mathdoc 的路径含 `数学学院\公共课\高数\讲义` → **同时满足**）。
- `scope_of()` 因为 **mathdoc 先判** → 返回 `mathdoc` → 与字面 `gmath` 不等 → 误报「错配」。
- 但 `in_scope(h, 'gmath')` = **True** → 实际能命中，**标注是对的**。
→ **与 m02 方向相反**：m02 的标注 `kmath`（规则是 `考插数学习题资料`/真题目录，**不含** `数学学院`）真的够不到 mathdoc 答案；c03/c08 的 `gmath` 够得到。
→ **判据必须用 `in_scope()` 而非 `scope_of()` 字面比较。**
