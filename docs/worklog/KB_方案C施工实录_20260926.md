## 四、步骤 2 · 方案 C 实测（核心结论）

### 4.1 规则试算结果

在 233 个 OCR 缓存文件上跑确定性规则：

| 规则 | 命中数 | 是否对公式有效 |
|---|---|---|
| `multi_space`（3+空格归一） | **16688** | ❌ 无效（打散是「单字母+单空格」，不匹配） |
| `pua_math`（私有区字符清除） | 1181 | 🟡 仅清理，不还原符号 |
| `1n → ln` | 56 | ✅ 有效 |
| `1im → lim` | 22 | ✅ 有效 |
| `lim\| → lim` | 5 | ✅ 有效 |
| `ctrl_clean` | 0 | — |

**真正对公式有效的规则 = 83 处**，分母 **221 条打散片段** → **覆盖率 0.6%**。

### 4.2 命中数虚高的原因

`multi_space` 占 95%，但它匹配的是「3 个以上连续空格」。而 OCR 打散的实际形态是：

```
f'(x): 当1≤x≤e时：f(x)单增；当x≥e时，f(x)单减
lim 科兴插 n→ √4n²-1² V4n²-2 √4n²-n²
```

即**「单字母 + 单个空格」交替**，**不是** 3 连空格。规则打不到。

### 4.3 规则救不了的本质

重度打散的形态是**二维公式被压成一维**：

| 原文（应还原） | OCR 实际输出 |
|---|---|
| $f(x) = \frac{p+q}{2}$ 处的证明 | `f(p)=f(P+q)+(p-P+q p+q)² f"(5)` |
| $\lim_{n\to\infty}\sum$ | `lim 科兴插 n→ ∑e”` |

**这需要理解二维排版语义，规则无法完成** —— 施工单 §1.2 的判断（「本机免费路径解决不了」）**是对的**。
