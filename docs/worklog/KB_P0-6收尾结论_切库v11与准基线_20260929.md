## 七、方法论复述（铁律）

1. **跨库对比必须 `--both` 同进程**。`--cold` 只是「重排冷」（`kb_eval.py` L93 只清 `rerank_cache_v4.json`，**不动 `rewrite_cache_v4.json`**），跨库实验会含隐藏变量 → 本轮曾先后得出 82.4% / 79.4% / 76.5% 三个不同 Hit@1。
2. **报数字必须声明冷/热口径**。
3. **重排走本地 `qwen2.5:7b`（temp 0.15）非确定性**，单跑一次不能当定论。
4. **同名文件多目录**（如两份 `算法与数据结构大纲.pptx` 分属不同目录）→ **判条目必须打印完整路径**，只看 basename 会误判。
5. **脚本一律只写不删**；清理动作交老板人工决定。

## 附录 A · 勘误 #194（2026-10-01 补记，交叉复核 RAG 线施工单 #200）

### A.1 事实

`clear_rr_cache()` 旧实现**只清磁盘、不清内存**：

- `kb_search_v4.py` L274 的 `_RR_CACHE` 是**模块级** `JsonCache` 单例；
- `kb_search_v3.py` L86-90：`JsonCache.__init__` 在**构造时（= import 时）**就把磁盘 json 读进内存字典 `self.d`；
- 旧 `clear_rr_cache` 只 `os.replace` 磁盘文件（`kb_eval.py` L95-115），`_RR_CACHE.d` **纹丝不动** —— 源码中 `_RR_CACHE` 出现 **0 次**。

**实测证据**：`import kb_search_v4` 后 `len(_RR_CACHE.d) == 132`（磁盘 `cache\rerank_cache_v4.json` 71289 B）。

### A.2 由此产生的两个错误认知

| 旧认知 | 实际 |
|---|---|
| 「`--both` 冷热差 +0.0pt ⇒ 缓存未污染结论、可信」 | **结构性恒为 0**。warm 与 cold 的 key 相同 → warm 必然命中 cold 写回内存的结果 → 差恒 0，**与 LLM 是否确定无关**。该行零信息量。 |
| 「`--cold` = 真冷算」 | **同进程内不生效**（内存未清）。仅**跨进程**（新 python 进程 + 磁盘已清）才等于真冷算。症状：冷档出现 0.1~0.4s 的"秒算"条目。 |

### A.3 对本件数字的处置（不单向作废）

| 项 | 处置 |
|---|---|
| 冷档 `79.4 / 94.1 / 97.1` | **保留**。逐条耗时 4.8~29.6s（33 条真算）；唯一 0.4s 的 c06 候选集 `n=2`，按 `kb_search_v4.py` L495-496 `len(cands)<=2 → return cands` 跳过重排，**非缓存命中**。 |
| MRR `0.870` | 正文笔误，JSON 实数 **0.875**（`round(mrr,3)`），以 JSON 为准。 |
| §3.1「双源逐位吻合 ⇒ 可信」 | **推理作废，数字保留**。逐位吻合可由「两源命中同一批旧缓存」或「warm 复用 cold」解释，**不构成独立验证**。 |
| §七 第 1 条「跨库对比必须 `--both` 同进程」 | **降级为：跨进程各跑 `--cold`**（或修复后用 `--both`）。同进程 `--both` 的冷档在修复前不可信。 |

### A.4 已实施的修复（2026-10-01）

`kb_eval.py::clear_rr_cache()` 增加内存单例同步清空：

```python
_mem_n = len(k4._RR_CACHE.d)
k4._RR_CACHE.d = {}
k4._RR_CACHE._dirty = 0
```

- **回滚点**：`kb_eval.py.bak_20261001_0840_memfix`（原文件 sha256 前16 `e1e0161d4343a9bf`，13801 B）
- **验证**：monkeypatch 到临时路径实测 —— 内存 132 条 → 0 条，`_dirty` 7 → 0，**PASS**；真实缓存文件未被触碰。

### A.5 新增量级警告（与 #200 的 B 部分结论一致）

**34 条样本上 Hit@1 的批次间波动 = ±1 条 = ±2.9pt。**
同配置（v11 + `cands_n=80`）跨进程两次真冷算实测 **79.4% vs 82.4%**。
→ **差 1~2 条的对比一律不足以定论**，同样适用于 `cands_n` 30 vs 80 的消融（首轮"Δ=0.0"另有缓存污染：cn80 首轮冷档 `sum=218s`，远低于两次真冷算的 237s / 487s）。

## 附录 B · 切库净收益勘误：+5.9pt → +2.9pt（2026-10-01 补记，总线 #206）

### B.1 触发

RAG 线工兵按 #201 定稿口径（**跨进程各跑 `--cold`**）重取真冷基线（总线 #203 / #204）：

|---|---|---|---|---|---|
| **v11@cn80** | **79.4%** | 94.1% | 97.1% | 0.875 | 0 |
| **v10@cn80** | **76.5%** | 94.1% | 97.1% | 0.844 | 0 |

（c07 两库 `rank=None`，稳健成立。）

### B.2 勘误内容

§一 与 §3.2 中「较 v10 提升 **+5.9pt** Hit@1」所依据的 **v10 冷 = 73.5%** 取自同进程 `--both` 的冷档，属**附录 A.2 所述的无效口径（假冷）**，不可作准。

| 项 | 旧（假冷口径） | 新（真冷口径 · 跨进程 `--cold`） |
|---|---|---|
| v10 冷 Hit@1 | 73.5% | **76.5%** |
| v11 冷 Hit@1 | 79.4% | 79.4%（与 08:06 本件冷档 + 工兵 #203 **逐位一致**） |
| **净收益** | **+5.9pt** | **+2.9pt** |

### B.3 ⚠️ 幅度未超噪声带 —— 不得直接宣称「切库显著有效」

按 A.5 量级（34 条样本单次波动 ±1 条 = ±2.9pt）：

- v11 真冷**两**跑 = **79.4 / 82.4**；
- v10 真冷**仅一**跑 = **76.5**；
- v10 与 v11 下界（79.4）之差恰 **2.9pt = 1 条**。

→ **「v11 ≥ v10」方向成立，但 +2.9pt 的幅度在单次跑下不显著**。坐实净收益须 v10 / v11 **各再跑 2~3 次真冷取中位数**。

### B.4 未受影响

- **v11 现役准基线不变**：`79.4 / 94.1 / 97.1 / MRR 0.875`（已双次真冷复现，可信度升级）；
- c07 两库 `rank=None` 稳健；越域 0 / auto 路由 100% 不变；
- 本次 v11 `Hit@3 = 94.1%`（此前一轮 97.1%）亦在 ±1 条带内，**非矛盾**。
