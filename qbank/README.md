# 评测集说明

这里是**评测用例**，不是题库。

## 里面有什么

每个用例是一条 JSON：

```json
{"id": "e01",
 "q": "<查询语句 —— 自己构造，模拟真实提问>",
 "scope": "<应在哪个域检索>",
 "expect": ["<期望命中的文档名 1>", "<文档名 2>"],
 "note": "<为什么这么设计>"}
```

四份用例侧重点不同：

| 文件 | 用途 |
|---|---|
| `eval_set.jsonl` | 通用基线，日常回归跑这个 |
| `eval_set_three.jsonl` | 三域交叉，检验域路由是否正确 |
| `eval_set_three30.jsonl` | 30 条放大版，用于显著性与抖动测量 |
| `eval_set_fudan.jsonl` | 单来源深挖，检验跨文档去重能力 |
| `eval_kbacc.jsonl` | 端到端问答准确率（不是召回率） |
| `qbank_meta.json` | 题库统计量：知识点分布 / 题型分布 / 打标来源配比 |

## 为什么题库正文不在这里

原仓库里有一份 `questions_math.jsonl`（1832 道题的 OCR 全文，1.2 MB）—— **没传**，因为它有版权。
这里只留**统计量**（`qbank_meta.json`），既保留了"题库长什么样"的信息，又不碰正文。

## 关于机构名

`expect` 和 `note` 里出现的来源标识已泛化为 `院校A/B/C`、`机构A`。
这是刻意的：这些字段原本指向私有的语料文件名。

**所以你需要替换**：把 `expect` 里的值改成你自己的语料文件名，评测才有意义。
结构不用动 —— 直接跑：

```bash
py -3.12 kb_eval.py --set qbank/eval_set.jsonl --count 5
```

## 两条方法论（踩出来的，比代码值钱）

**① `--both` 的同进程冷热对比，不能证明跨进程可复现。**
同进程跑冷热，测的是"这个 Python 解释器里缓存有没有生效"；使用者面对的是**下一次全新启动**。
真要检验，必须**跨进程双跑**。

**② 先校准尺子，再量身高。**
想测"负载会不会影响结果"，前提是先确认"无负载时结果本身稳定"。
这一步不成立，整场实验都不成立 —— 这是设计实验前必须先答的三问之一。
